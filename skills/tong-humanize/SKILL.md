# Tong Humanize (去 AI 味与主编终审)

写文章就用这套。去 AI 味与主编终审是交稿门禁，不是用户口头令。

主编不负责注水润色，**主编负责拿刀剪枝**。改「怎么说」，不改「说什么」。对事实虚构持一票否决权，对过度拔高、假大空鸡汤与 AI 模板腔坚决剔除。

**Platforms: macOS, Windows, and Linux.** Same `SKILL.md` + `scripts/scan.py`. Do not regenerate a scanner.

---

## Workflow

`<skill-dir>` 为本 `SKILL.md` 所在目录。若缺少 `python3`，Windows 下使用 `py -3`。

1. **定栏目。** 判断不了就问一句，别猜。写文章没说发哪，不要默认 `general`。

| 用户说法 | `--lane` |
|---|---|
| 公众号 / 主号 / 长文 | `wechat` |
| 每日速览 / 简报正文 / 写速览 | `brief` |
| 小红书 / 小绿书 | `xhs` |
| 去AI味 / 润色 / 没说栏目 | `general` |
| 写文章 / 写一篇 / 没说发哪 | 问一句栏目 |

2. **有稿就改，没稿就写。** 用户贴了原文或给了文件 → 先扫再改。用户要写一篇 → 按硬规则直接写，写完再扫。不要先交一版塑料稿等人说「去AI味」。

用户已有文件就扫原路径；对话里写/改则走 stdin，不要为了扫描建 `tmp/`：

```bash
python3 "<skill-dir>/scripts/scan.py" path/to/draft.md --lane wechat
python3 "<skill-dir>/scripts/scan.py" - --lane wechat
```

`--list` 看栏目和检查项。输出分两档：

| 档 | 含义 | 你要做的 |
|---|---|---|
| `FAIL` | 硬伤（套话、喊话、堆叠副词、栏目标点、否定列举） | 必须改，改到退出码 0 |
| `WARN` | 要人判（单个「不是而是」、闭环 / 抓手 / 本质上、首先其次最后） | 逐条判：留就留，改就改。交稿时一句话说明 |

3. **按档位改。** 改稿时 FAIL 当硬伤，没命中的句子尽量不动。从零写没有「原文句子」，扫到 FAIL 再修，不要为了过门禁把稿子写空。

| 档位 | 怎么判 | 改多深 |
|---|---|---|
| 轻度 | 硬伤很少，结构还像人 | 只换词、拆套话 |
| 中度 | 套话 + 三毒 + 连接词成片 | 再去书面腔 |
| 重度 | 整段在演深刻 | 重写病灶段，其余仍少动 |

4. **主编负向剪枝（Negative Pruning）。**
   - 宁可删空，不可注水。
   - 对冗余说教段落直接动刀删除（`delete_suggestions`），拒绝为了凑字数而硬保。

5. **九维终审复核（Chief Editor Review）。**
   对照下方九大维度逐项复核（合格标准：Score >= 85 且 Fact Score == 100）。

6. **再扫与交稿。**
   改完必须再跑一遍 `scan.py`，直到退出 0。交稿提供：定稿正文 + 扫描结果说明 + 主编剪枝要点。

## 主编九大终审维度 (Chief Editor Checklist)

1. **事实真实性 (Fact Check, 一票否决)**：凡是 AI 擅自增加的重大事实、捏造的数据或虚构经历，事实分归零，坚决打回或删净。
2. **逻辑自洽性**：观点是否由具体细节支撑，前后论断是否存在自相矛盾。
3. **题文一致性**：标题是否透支信用？正文是否撑得起标题承诺的期待。
4. **拒绝预制剧本道具（一票否决）**：凡出现“凉透的外卖咖啡”、“杯壁凝结的水珠”、“揉了揉发红的眼角”、“冷白微光”、“慢吞吞推车的保洁阿姨”等 AI 刻板摆拍细节，坚决换成真实业务/生活动作。
5. **强行上价值与顾问爹味拦截 (Anti-Preachy)**：
   - 坚决剪掉将日常小事硬扯到“时代浪潮/资本宿命”的假深刻。
   - 坚决剪掉麦肯锡咨询式装腔作势假金句（如“当……边际成本趋近于零，……隐形成本被无限放大”），替换为具体的泥土气与工程隐喻。
6. **调性防两极分化**：既不许出现假大空的 AI 八股腔，也不许滑向无信息密度的纯口语碎碎念或论坛口嗨。保持**有智识密度、有叙事节制、有文学质感**的现代非虚构专栏质感。
7. **情绪健康度**：是否沦为单纯戾气发泄或怨妇口吻？
8. **金句密度**：全文金句是否超过 3 处？过多则要求砍去，保留阅读呼吸感。
9. **节奏与排版**：以 1~3 行短段落为主，禁止连续 3 段以上的大块理论陈述。

## 硬规则

1. **跑 bundled 脚本。** 不要手写另一份禁用词表来「代替扫描」。
2. **不新增事实。** 数字必须来自原文、用户或命令输出。没有数就写轻（「不少 / 一大截」），严禁胡乱编造。
3. **不换人。** `general` 只去塑料味，不灌口癖。保持作者原本的音色。
4. **不喊话收尾。** 「放话了 / 欢迎打脸 / 回来谢我 / 点个在看」整段删。说完就停。
5. **自嘲可以，吹牛不行。** 不写没跑过的「轻松搞定」「效率翻倍」。

## 「不是 A 而是 B」先判毒再修

脚本只报 WARN，判定归你。先归类：

| 毒 | 判定 | 修 |
|---|---|---|
| 假靶子 | 没人做过前半句那个判断 | 只留 B |
| 同义替换 | A 和 B 是同一件事 | 合成一句 |
| 硬凑 | 删掉脚手架意思不变 | 删 |
| 好用法 | 真有人会选 A，且 A ≠ B | 可留 |

NNY（「不是 X。不是 Y。只是 Z。」）是 FAIL，默认删前两句。修法细节见 [references/structures.md](references/structures.md)。

---

## 术语还是空话

`闭环 / 抓手 / 本质上 / 对齐 / 颗粒度` 报 WARN。判法一条：**把这个词删掉，句子还剩不剩具体内容？**

- 「温控闭环已经调稳，超调从 8% 收到 2%」删了「闭环」句子塌，是术语，留。
- 「赋能业务，形成增长闭环」删了什么都不剩，是空话。这种业务搭配脚本直接 FAIL。
- 「本质上这就是个缓存击穿」删掉「本质上」意思不变，删。

## 栏目差异

- `general`：套话、否定列举、堆叠副词。破折号每篇 ≤2。冒号和引号不禁。
- `wechat`：再加冒号 / 破折号 / 英文或弯引号清零。引用用「」。每段表情 ≤1–2，只放情绪高点。
- `brief`：冒号每篇 ≤2。读者是泛人群，专业黑话要解释或删。
- `xhs`：破折号和弯引号仍禁，冒号放开。

---

## 家规放本地，不放 skill

每个号都有自己的红线：不能出现的产品名、不能暴露的作者身份、被毙过的收尾句。写在本地文件里，扫描时传进去：

```bash
python3 "<skill-dir>/scripts/scan.py" draft.md --lane brief --rules ~/.tong/house-rules.txt
```

## Quality Gate

- `scan.py` 退出码为 0，或已标明 `[需复核]`。
- 事实真实性 100% 严守，无幻觉数据与虚假经历。
- 主编九维审核通过（无强行上价值，金句 ≤3 处，短段落排版）。
- 每条 WARN 均有明确去留说明。
